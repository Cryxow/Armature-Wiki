# ▶️ Анимации и визуальные представления

## Просмотр моделей в автономном режиме и постоянные представления

Эти операции требуют совместимого плагина/API JAR версии 2.0.0. В документации Javadoc версии 1.3.0 они не описаны.

Выберите загруженную модель явно для воспроизведения конечной анимации без файла профиля, сопоставителя предметов или предыдущего вызова API:

```java
ArmatureApi.tryAnimations().ifPresent(api ->
    api.play(playerId, "arm_rifle", Map.of(
        "name", "inspect",
        "speed", 1.25,
        "duration", "40t",
        "can-be-cancelled", true
    )).thenAccept(result -> {
        if (!result.accepted()) logger.fine("Playback: " + result.status());
    })
);
```

Вызов временно заменяет вид игрока через активный рендерер. Модель и активы пакета ресурсов должны быть уже загружены. Armature обнаруживает модели независимо от сопоставления предметов профиля. Фактический инвентарь не меняется. После завершения конечного действия Armature восстанавливает представление, соответствующее предмету, **удерживаемому в этот момент**. Неизвестная модель или отсутствующая анимация отклоняются до замены существующего вида. Сбой рендерера после монтирования освобождает временный вид и восстанавливает сопоставление предметов.

Будущее разрешение происходит после готовности модели и принятия запроса на воспроизведение, а не после окончания анимации. Возвращенный обработчик представления может закрыть именно эту генерацию рано. Закрытие старого обработчика не может закрыть новое представление.

Для постоянного движения, повторяющихся действий, аддитивов и условий откройте одно представление с точным содержимым раздела YAML `animations`:

```java
var presentation = new ArmaturePresentation("arm_rifle", Map.of(
    "movement", List.of(Map.of("animation", "base")),
    "actions", List.of(Map.of(
        "trigger", "myplugin:inspect",
        "condition", List.of("event.argument.allowed == true"),
        "hide-vanilla-hand", true,
        "animation", Map.of(
            "name", "inspect",
            "duration", "40t",
            "speed", 1.25,
            "cooldown", "10t",
            "can-be-cancelled", false
        )
    ))
));

api.openPresentation(playerId, presentation).thenAccept(result -> {
    result.handle().ifPresent(handle -> {
        // Store this handle in the integration's per-player state to close later.
        presentationHandles.put(playerId, handle);
        api.trigger(playerId, "myplugin:inspect",
            ArmatureSignalData.of(Map.of("allowed", true)));
    });
});

// When the integration relinquishes this view:
var handle = presentationHandles.remove(playerId);
if (handle != null) api.closePresentation(playerId, handle);
```

Полный конструктор также принимает дерево `variables`, смещение модели, скорость покачивания модели и видимости по умолчанию для основной руки. Карты/списки глубоко копируются перед планированием. API использует тот же парсер и оценщик правил, что и YAML, включая валидацию неподдерживаемых свойств и некорректных комбинаций:

| Раздел | Поддерживаемые параметры |
| --- | --- |
| Правило `movement` | `when`, `hide-vanilla-hand`, `animation` |
| Анимация движения | `name` (строка/список), `selection`, `speed`, `blend-in`, `blend-out`, `sway-rate`, `loop`, `start`, `end` |
| Правило `actions` | `trigger`, `condition`, `consume`, `hide-vanilla-hand`, `animation` |
| Анимация действия | `name` (строка/список), `selection`, `duration`, `speed`, `blend-in`, `blend-out`, `cooldown`, `can-be-cancelled` |
| Правило `additives` | `when`, `animation`, `playback`, `group`, `priority`, `weight`, `blend-in`, `blend-out`, `bones`, `channels`, `position-gain`, `rotation-gain`, `reference` |
| Аддитивная анимация | `name` (строка/список), `selection`, `speed` |
| Картирование весов | `parameter`, `input`, `output`, `easing`, `clamp` |
| Референсная поза | `animation`, `time` |

Единицы времени и значения по умолчанию совпадают с современным YAML (`t`, `s` или числовые тики, если это поле их принимает). Пропущенная длительность действия берется из загруженного клипа. Результат `consume` является решением маршрутизации. Пользовательская игра все еще принадлежит интеграции. Отправка триггера сама по себе не отменяет произвольное событие Bukkit.

Каждое открытое представление владеет новым состоянием правил. Повторные вызовы `trigger(...)` в этом виде разделяют таймауты и последовательности вариантов. Отдельные вызовы `play(player, model, options)` создают отдельные контексты. Их таймауты не разделяются. Используйте постоянное представление для систем оружия/навыков с повторяющимися триггерами.

Активен только один вид, принадлежащий API, на игрока. Он сохраняется при смене предметов до закрытия/замены, но освобождается при очистке сессии игрока (смерть, отключение, смена мира), перезагрузке плагина или отключении времени выполнения/игрока. Открытие замены уважает текущее неотменяемое действие. Явное закрытие представления полностью его уничтожает. Конфигурированный каталог профилей остается только для чтения и не содержит этих временных видов. Идентификаторы временных видов в данных жизненного цикла/операций начинаются с `api.` и не являются ID профилей YAML.

Пока активен этот режим, неподкреплённые ссылки на активы и сырое воспроизведение используют его модель/правила. Встроенное устаревшее `ArmatureAction` не переходит на профиль предмета в руке. `trigger(...)` — это алиас, согласованный с YAML, для `signal(...)`. Существующие перегруженные сигналы остаются совместимыми.

## Каналы действия, цикла и аддитивного слоя

Новые интеграции должны использовать `ArmatureAnimationReference` вместо угадывания, является ли строка конечным действием, постоянным циклом или аддитивным слоем:

```java
var api = ArmatureApi.animations();

api.playAsset(playerId, ArmatureAnimationReference.action("inspect"));
api.startLoop(playerId, ArmatureAnimationReference.loop("aim"));
api.triggerAdditive(playerId, ArmatureAnimationReference.additive("recoil"));
```

Используйте `ArmatureAnimationReference.profile(profileId, assetId, channel)`, когда профиль должен быть явным. Профиль всё равно должен быть тем, который рендерится для предмета в руке игрока. Armature возвращает `PROFILE_NOT_ACTIVE` вместо того, чтобы молча заменить это представление.

Принятые операции возвращают `ArmatureOperationResult`. Его хендл ограничен игроком, профилем, каналом и монотонно возрастающим токеном времени выполнения:

```java
var request = api.triggerAdditive(playerId,
    ArmatureAnimationReference.additive("recoil"));
request.thenAccept(result -> result.handle().ifPresent(handle ->
    api.stop(playerId, handle)
));
```

Остановка старого хендла никогда не останавливает более новую замену. Устаревший хендл возвращает `HANDLE_NOT_ACTIVE`. Прямой цикл остаётся выбранным, пока он не будет остановлен, предмет/профиль не изменится, Armature не перезагрузится или время выполнения не будет отключено.

`catalog()` возвращает неизменяемую снимок профиля с id действия, цикла, аддитивного слоя и сигнала. `snapshot(playerId)` возвращает состояние представления и активные id аддитивных слоёв для одного онлайн-игрока. Ни один из методов не exposes состояние игры.

## Профиль-зависимые и совместимые вызовы

`play(UUID, String)` — это совместимый API для устаревшего id действия, определённого администратором, в профиле предмета, который сейчас держит игрок:

```java
animations.play(player.getUniqueId(), "inspect");
animations.playAction(player.getUniqueId(), ArmatureAction.FIRE);
```

`playAnimation(playerId, animationId)` выбирает конкретную конечную анимацию в активном профиле, в том числе анимации, определённые прямо в современных правилах действий. `startLoop(playerId, assetId)` принимает идентификатор встроенного цикла или точный идентификатор ресурса зацикленной анимации. Чтобы получить дескриптор, используйте перегрузку с указанием канала.

Если интеграция сама задаёт имена анимаций, используйте прямые методы. Для выбора модели им нужен активный профиль предмета или представление API. Запрошенный клип может отсутствовать в профиле. При запуске движок проверяет наличие клипа в загруженной модели.

```java
animations.playRawAnimation(playerId, "fire");
animations.startRawLoop(playerId, "aim");
```

Для интеграций, владеющих именами анимаций, используйте сырые методы. Они требуют активного профиля предмета или представления API для привязки рендеримой модели. Запрашиваемый клип не должен быть указан в этом профиле. Движок валидирует актив против загруженной модели в момент воспроизведения:

Перегрузка enum отправляет встроенное действие Armature. `startLoop` — это явная форма, ориентированная на состояние, для постоянных действий, таких как `IDLE`, `AIM` или `CROSSBOW_CHARGE`; `stopLoop` очищает выбранный цикл. `stopAction` отменяет текущий одноразовый и возобновляет выбранный цикл.

```java
animations.startLoop(playerId, ArmatureAction.CROSSBOW_CHARGE);
animations.stopAction(playerId);
animations.stopLoop(playerId);
```

Когда интеграция уже знает id профиля, она может сделать выбор явным:

```java
animations.playAnimation(playerId, "m4a1", "inspect");
animations.playAnimation(playerId, "m4a1", "swing");
```

Выбранный профиль должен быть тем, который в данный момент рендерится для предмета в руке игрока. Это предотвращает тихую замену представления игрового предмета анимацией. Результатом является `PROFILE_NOT_ACTIVE`, когда профиль существует, но не совпадает с предметом в руке.

Эти вызовы API воспроизведения не изменяют предмет, патроны, урон или состояние перезарядки, и не отменяют событие, принадлежащее вызывающему. Плагин игрового процесса остается ответственным за эти правила.

## События жизненного цикла

API отправляет события Bukkit для принятых конечных анимаций:

- `ArmatureAnimationStartEvent` открывает `getProfileId()`, `getActionId()`, `getAnimation()` и `getToken()`.
- `ArmatureAnimationEndEvent` открывает те же поля, что и `getReason()`: `COMPLETED`, `CANCELLED`, `REPLACED` или `REMOVED`.

Переходы цикла — это внутренние переходы рендера и не вызывают событий жизненного цикла. Событие конца служит надежным крючком для запуска последующего навыка, принадлежащего игре. Оно не означает, что Armature владеет этим состоянием игры.

## Результаты и состояние

`ArmatureAnimationResult.Status` различает принятую воспроизведение от отсутствующего профиля/действия, таймера перезарядки, активного неотменяемого действия, недоступного игрока, устаревшего обработчика или отказа рендера. `ArmatureAnimationState` и `ArmatureAnimationSnapshot` открывают только данные представления: ключ текущего предмета, желаемый цикл, активную анимацию, аддитивные слои и оставшиеся тики. Они намеренно не открывают состояние игры.

```java
animations.getState(playerId).thenAccept(snapshot -> snapshot.ifPresent(state -> {
    if (state.hasActiveAction()) {
        plugin.getLogger().fine("Armature action: " + state.activeActionId()
            + " / animation: " + state.activeAnimation());
    }
}));
```

Конструктор `ArmaturePresentation` позволяет использовать дерево переменных в строке для временного просмотра, принадлежащего API. Это не дает разрешения на локальные `variables:` блоки в профилях YAML: профили на диске используют общий `plugins/Armature/variables.yml`.
