# 📡 Сигналы

Плагины могут отправлять сигналы с именным пространством через современные правила `animations.actions`. Старая карта `bindings` (и совместимая с ней карта `triggers`) всё ещё принимается загрузчиком совместимости. Условие действия оценивается Armature, и его значение `consume` возвращается как метаданные. Armature не может отменить событие, которое принадлежит другому плагину.

```yaml
animations:
  actions:
    - trigger: skript:weapon.pistol.fire
      condition: player.on-ground == true
      animation:
        name: pistol_fire
        duration: 6t
      consume: false
```

```java
ArmatureApi.animations()
    .sendSignal(playerId, "skript:weapon.pistol.fire", Map.of())
    .thenAccept(result -> {
        if (result.matched() && result.animation().accepted()) {
            // The gameplay plugin already performed its own firing logic.
        }
    });
```

Это примитив, используемый опциональными интеграциями Skript, MythicMobs и Denizen, встроенными в `Armature.jar`. Armature регистрирует их эффекты, механики или команды только когда присутствует соответствующий хост-плагин. В нативном Skript или Denizen нет магии `emit` синтаксиса.

Для метаданных сигналов с типами используйте ограниченные скалярные данные. Поддерживаются строки, булевы значения и конечные числа. Объекты Bukkit, сущности, стеки предметов и необязанные нагрузки отклоняются на границе API:

```java
api.emitSignal(playerId, "myplugin:weapon.fire",
    ArmatureSignalData.of(Map.of("ammo", 7, "mode", "semi")));
```

Перегрузка совместимости `Map<String, String>` подчиняется тем же ограничениям: максимум 64 записей, ключи длиной до 128 символов и строки длиной до 1024 символов.

Текущий триггерный рунтайм получает совместимый вид строки. Плагины геймплея остаются ответственными за валидацию и модификацию своего урона, задержек, урона и отмены событий.

## Алиас триггера, выровненный по YAML

```java
api.trigger(playerId, "myplugin:inspect",
    ArmatureSignalData.of(Map.of("allowed", true)));
```

`event.argument.allowed` доступен для совпадающего современного условия действия. Используйте точное имя с именным пространством в YAML. Сигналы возвращают статус совпадения/потребления и результат анимации. Геймплей, принадлежащий вызывающему, решает, как им воспользоваться.

Встроенный адаптер WeaponMechanics reload-input явно интерпретирует потребленный сигнал `weaponmechanics:reload`, отменяя свой собственный событие-поставщик. Это поведение конкретного адаптера не является автоматической отменой произвольных событий Bukkit, Skript, MythicMobs или Denizen.

Протестируйте разрешенные и запрещенные нагрузки, отмену перезарядки, защищенные действия и недоступных игроков. Отправка сигнала без соответствующего правила не является воспроизведением клипа. См. [Условия](../../nachalo-raboty/profili/conditions.md).
