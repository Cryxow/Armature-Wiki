# 🎬 Правила действий

Действия используют событие `trigger` и опционально `condition`:

```yaml
animations:
  actions:
    - trigger: block:place
      condition:
        - item.main-hand.type == minecraft:stone
      animation:
        name: block-place
        duration: 8t

    - trigger: api:custom-hit
      condition:
        - event.argument.critical == true
      animation:
        name: hit
        duration: 6t
      consume: false
```

Действия всегда используют эксклюзивный канал `replace`. Поля `mode` нет. `can-be-cancelled: false` защищает активное действие от замены. Оно не создаёт наложение. Аддитивные правила — это отдельный канал, составленный Armature.

`consume: true` имеет значение для владельца события, поддерживающего отмену, например, для обычного клика правой кнопкой мыши или ввода от поставщика. Для сигнала API/Skript/Denizen он возвращается в `ArmatureSignalResult`. Внешний вызывающий всё равно владеет отменой игрового процесса.

## Варианты анимации

С `render.backend: native` имена активов анимации выбираются свободно, включая `idle`, `walk`, `idle_fly`, `walk_fly`, `spawn` и `jump`. Движение/действие/аддитивные правила и их начальные/конечные/ссылочные клипы используют явно настроенные имена. Клип не начинается автоматически из-за имени. Та же политика применяется к наследуемым профилям и представлениям API, при запуске и перезагрузке профиля. Имена должны быть непустыми и соответствовать клипу в модели. Бэкенд BetterModel сохраняет свою валидацию имен с зарезервированными именами.

Каждый `animation` принимает либо одно имя актива, либо маппинг:

```yaml
animation:
  name: [swing, swing_1, swing_2]
  selection: random
  duration: 6t
  speed: 1.0
  cooldown: 3t
  can-be-cancelled: true
```

| Поле | Движение | Действие | Аддитивное | Значение |
| --- | --- | --- | --- | --- |
| `name` | да | да | да | Один актив или список вариантов. |
| `arms` | необязательно | необязательно | нет | `one` (по умолчанию) или `both`. Движение/действие в основной руке может использовать оба скелета. |
| `selection` | да | да | да | `sequence` или `random`. По умолчанию `sequence`. |
| `speed` | да | да | да | Множитель воспроизведения, отличный от нуля. Отрицательные значения проигрывают анимацию в обратном порядке. |
| `blend-in` | необязательно | необязательно | нет | Длительность смешивания при входе. По умолчанию `2t` для движения и `1t` для действия. |
| `blend-out` | необязательно | необязательно | нет | Длительность смешивания при выходе. По умолчанию `2t`; `0t` отключает его. |
| `sway-rate` | да | нет | нет | Опциональное переопределение движения. Наследует `model.sway-rate`, если не указано. |
| `loop` | истина | ложь/не указано | n/a | Правила движения должны быть циклическими. |
| `start` | необязательно | нет | нет | Однократная анимация перед циклом движения. |
| `end` | необязательно | нет | нет | Однократная анимация после выхода из цикла движения. |
| `duration` | нет | необязательно | нет | Длительность действия резервного варианта, в тиках или секундах. |
| `cooldown` | нет | необязательно | нет | Задержка между успешными действиями. По умолчанию `3t`. |
| `can-be-cancelled` | нет | необязательно | нет | Может ли другое действие замены прервать его. По умолчанию `true`. |

Для конечных действий известная движку длительность анимации имеет приоритет над заданной резервной длительностью. При `selection: sequence` выбор переходит к следующему клипу после каждого успешного запуска. При `random` клип выбирается независимо при каждом запуске. У всех вариантов одного правила общий интервал повторного запуска.

## Защищенные действия и переходы

`can-be-cancelled: false` защищает активное конечное действие от обычной замены. Изменения вариантов/составов, ожидающие подтверждения, пересчитываются после завершения защищенного действия. Изменения предметов/разъединения и очистка рендера все еще требуют обработки жизненного цикла. Этот флаг не является блокировкой игрового процесса.

Принятый клип снятия использует исходящий экземпляр/позу. Быстрая последовательность A → B → A может вернуть соответствующий исходящий профиль/экземпляр модели. Отрицательное ненулевое `speed` воспроизводит авторский таймлайн в обратном порядке. Нулевая скорость недействительна.

`consume` является решением о поставщике/вводе, а не автоматической логикой перезарядки патронов. Некоторые отменяемые сигналы ввода/поставщика могут быть использованы. См. [WeaponMechanics](../../rasshirennye-vozmozhnosti/podderzhivaemye-plaginy/weaponmechanics.md) для поведения отмены ввода перезарядки. Сохраняйте авторитет оружия в этом плагине.

Проверьте повторные нажатия, отказ в запуске до истечения интервала, прерываемые и защищённые клипы, переключение на стандартный предмет и обратно. В разделе [Основная и вторая рука](hands.md) описано влияние `arms: both` на одновременные анимации.
