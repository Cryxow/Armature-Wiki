# 🧩 Аксессуары и составные модели

Составная модель монтирует независимые модели на кости основной модели. Она отличается от переключения существующих костей через настройку аксессуара для игрового движка. Нативный движок рендеринга владеет этим представлением. Состояние игры остается в WeaponMechanics или вашем собственном плагине.

```yaml
charm_star:
  type: attachment
  model:
    name: charm_star
  physics:
    enabled: true
    frequency: 3.0
    damping: 0.8
  animations:
    movement:
      - animation: idle
    actions:
      - trigger: weaponmechanics:fire
        animation: flash

scope_long:
  type: attachment
  model:
    name: scope_long
  physics:
    enabled: false
```

Статические аксессуары могут не иметь анимаций. Каждая ссылка создает независимые каналы анимации, таймеры перезарядки и пружины физики. Перезагружаемые профили могут объявлять свои собственные варианты и дочерние аксессуары. Они никогда не выбираются предметом в руке.

## Монтажи и варианты

```yaml
m4a1:
  match:
    item: weaponmechanics:m4a1
    when: variable.player-level >= 10
  model:
    name: arm_rifle
  attachments:
    scope:
      profile: scope_long
      attach-to: {parent: base, bone: scope_socket}
      when: weaponmechanics.has-attachment:scope_long == true
    charm:
      profile: charm_star
      attach-to: {bone: charm_socket}
      transform:
        position: [0, 0, 0]
        rotation: [0, 0, 0]
        scale: [1, 1, 1]
      when:
        permissions:
          any: [cosmetics.charm.star, cosmetics.admin]
        all:
          - variable.charm-unlocked == true
  animations:
    movement:
      - animation: base
      - when:
          - weaponmechanics.aiming == true
          - attachment.scope.active == false
        animation: aim
      - when:
          - weaponmechanics.aiming == true
          - attachment.scope.active == true
        animation: aim_scope
    actions:
      - trigger: weaponmechanics:reload
        animation:
          name: reload
          can-be-cancelled: false
  variants:
    gold:
      when:
        permissions:
          any: [cosmetics.rifle.gold, cosmetics.admin]
        all:
          - variable.weapon-skin == gold
      model: {name: arm_rifle_gold}
      attachments:
        charm:
          model: {name: charm_star_gold}
          physics: {damping: 0.9}
```

Все названные активы, кости и клипы в этих примерах должны существовать в ваших моделях. `base` указывает основную модель текущего профиля. Родитель монтажа может также быть экземпляром сibling ID. Вложенные профили используют свои собственные локальные ID экземпляров. Диагностика показывает пути, такие как `charm/ribbon`. Неактивность родителя скрывает потомков. Родители оцениваются и монтируются перед детьми независимо от порядка объявления.

Позиция использует единицы Blockbench (16 на блок), поворот — градусы, масштаб — три положительных фактора. Геометрия монтируется в локальных координатах авторской модели без смещения сцены игрока компилятора. Итоговая анимированная/физическая поза родителя собирается один раз перед собственной анимацией/физикой ребенка. Имитация следует отмеченным физическим костям актива и остается эффектом пружины без столкновений. Пропущенные настройки физики наследуют глобальную конфигурацию.

`match.when` управляет активацией. Первая совпадающая версия в порядке YAML выигрывает. Отсутствие совпадений использует базовое представление. Версии не складываются. `variant.active` — это `base` или выбранный ID версии в текущем профиле. `attachment.<id>.active` описывает прямые крепления и доступен для условий анимации.

Условия выбора используют внешнее состояние и общие переменные. Условия версии/совпадения не могут зависеть от выбора или результатов анимации. Условия крепления могут использовать выбранный `variant.active`, но не активное состояние другого крепления. Другие условия анимации сохраняют существующий язык.

Условие `permissions` принимает непустые списки `any`, `all`, `none`. Несколько групп и другие критерии в блоке условия объединяются с AND. Существующие выражения `player.has-permission:<permission>` продолжают работать.

## Переопределения и жизненный цикл

Применяются переразрушаемые базовое → его выбранная версия → переопределения экземпляра. Поля модели/физики и записи аксессуаров объединяются по ключу. Каждая предоставленная категория анимации заменяет этот весь список. Пропущенные категории наследуются. Каждое крепление требует `profile` и `attach-to.bone` после объединения. Переопределения экземпляра могут заменить его модель, физику, анимации и детей. `enabled: false` отключает наследуемое крепление. Изменение `profile` экземпляра применяет его переопределения к новой ссылке.

Изменения ждут, пока представление содержит неотменяемое действие. При завершении пересчитываются условия и применяется последнее запрошенное сочетание. Изменения предмета, отключение, отключение и перезагрузка профиля/модели очищают экземпляры. Проверки аксессуара WeaponMechanics используют предмет владения рукой. Игровой процесс остается в WM.

Загрузка всех ссылок перед активацией. Неизвестные переменные/ссылки, дублирующие ID, циклы профиля/установки, невалидные поля и неподдерживаемые функции бэкенда отклоняют библиотеку. Ошибки перезагрузки сохраняют активную библиотеку. Валидация активов нативного движка проверяет все варианты и оверрайды перед публикацией пакета, включая кости установки, клипы анимации и аддитивные ссылки. Условия никогда не перестраивают пакет.

`/armature profile inspect <player>` включает выбранный вариант и пути/модели активного экземпляра. Автоматические проверки должны быть followed полным перезапуском сервера, загрузкой пакета и валидацией подключенного клиента для обеих рук, прицеливания, цепочек установок, физики и изменений во время защищенных действий.

## Совместимость рендера

Составная физика/на экземпляре требует нативный бэкенд. Текущий пучок рук Fabric не является транспортом сцены с композицией, поэтому композированное представление использует нативные ItemDisplays сервера и его требуемый пакет рендера. Удаление композиции возвращает совместимое представление для клиентского рендеринга. Не описывайте этот резервный вариант сервера как баг с отсутствующей моделью.

## Статичный пример аксессуара

```yaml
wiki_charm:
  type: attachment
  model:
    name: wiki_charm
  physics:
    enabled: true
    frequency: 3.0
    damping: 0.9

wiki_composite:
  match:
    item: minecraft:stick
  model:
    name: wiki_player
  attachments:
    charm:
      profile: wiki_charm
      attach-to:
        bone: charm_socket
      when:
        permissions:
          any: [cosmetics.charm, cosmetics.admin]
      transform:
        position: [0, 0, 0]
        rotation: [0, 0, 0]
        scale: [1, 1, 1]
```

Предоставьте `wiki_charm` и кость `charm_socket` главной модели. Предоставьте разрешение, перестройте/передайте активы и проверьте путь активного экземпляра. Поставьте флаг физики на кость аксессуара, чтобы сделать видимой его активную пружину.
