# 🗡️ Отображение предметов в руках

Визуальное состояние принадлежит профилю и независимо от анимации руки. Меняется только отображаемая копия Armature. Инвентарный предмет игрока и его компоненты остаются нетронутыми. Этот же раздел принимается в наследуемых профилях, использующих `model.name`.

Дуга может повторно использовать ветки `minecraft:using_item` и `minecraft:use_duration` исходной модели. Ванильная дуга меняется на 13 и 18 тиках:

```yaml
bow:
  match:
    item: minecraft:bow
  model:
    name: bow_arms
    held-item:
      mode: source
```

Для трезубца или щита, у которых анимация руки уже показывает действие, сохраняйте внешний вид остальной части даже во время использования предмета игроком:

```yaml
trident:
  match:
    item: minecraft:trident
  model:
    name: trident_arms
    held-item:
      mode: static
```

Используйте `mode: source` для этого трезубца или щита, когда нужны ветки использования в пакете. Выбор общий: определение исходного предмета читается после приоритета пакета ресурсов и разрешения наложения. Условия, не связанные с использованием, остаются в модели предмета для оценки Minecraft.

```yaml
shield:
  match:
    item: minecraft:shield
  model:
    name: shield_arms
    held-item:
      mode: static # change to source to display the pack's blocking model
```

Для кастомных моделей правила проверяются в порядке файлов. Каждый `model` ссылается на существующий `assets/<namespace>/models/<path>.json` в действующем пакете. Пропущенные ссылки приводят к отказу в генерации пакета вместо публикации поврежденного состояния:

```yaml
custom_bow:
  match:
    item: itemsadder:custom_bow
  model:
    name: custom_bow_arms
    held-item:
      mode: rules
      default: original
      rules:
        - when: item.use-ticks >= 18t
          model: mypack:item/custom_bow_pulling_2
        - when: item.use-ticks >= 13t
          model: mypack:item/custom_bow_pulling_1
        - when: item.using == true
          model: mypack:item/custom_bow_pulling_0
```

`item.using` и `item.use-ticks` относятся к руке, которая рендерится. `original` сохраняет обычную модель предмета в качестве резервного варианта. Правила выбирают алиас модели предмета, сгенерированный Armature. Они не меняют геймплей или длительность использования.

Чтобы сохранить ванильный предмет видимым в обычном режиме и показывать Armature только для выбранных событий, сделайте список разрешенных рендеров явным и оставьте включенным скрытие руки:

```yaml
model:
  name: baseball_bat
  hide-vanilla-hand: true
  render-events: [player:attack]
```

В качестве идентификаторов действий могут выступать `swing` или сигналы с пространственным именем, например `player:attack`. Список разрешенных действий контролирует видимость модели, но правило сопоставления под `animations.actions` по-прежнему определяет, какую анимацию воспроизводить. Для условного скрытия рук от первого лица требуется PacketEvents.

Чтобы модель оставалась загруженной, пока обычный предмет виден во время обычного движения, переместите скрытие руки в правила:

```yaml
model:
  name: baseball_bat
  hide-vanilla-hand: true

animations:
  movement:
    - when: player.speed >= 0
      hide-vanilla-hand: false
      animation: base
  actions:
    - trigger: player:attack
      hide-vanilla-hand: true
      animation: attack_1
```

Активное правило действия имеет приоритет над выбранным правилом движения. Правило без `hide-vanilla-hand` наследует значение от следующего уровня, затем от `model.hide-vanilla-hand`. Этот параметр контролирует только скрытие рук; `model.render-events` остается отдельным списком разрешенных моделей.

`animations` — это контейнер, а не реестр анимаций. Современный загрузчик отвергает `animations.definitions`, верхнеуровневые `actions` и `triggers`, а также `mode` в правилах действий. Анимации объявляются рядом с правилом с использованием этих идентификаторов.

Принятая действие `item:unequip` сохраняет исходящую модель активной до завершения авторской анимации, включая скорость воспроизведения. Дополнительные изменения слотов не закрывают ранее исходящие модели. Возврат к профилю во время раскрепления возвращает ту же модель и смешивает текущую позу с режимом надевания или циклом обычного движения, используя настройки смешивания входящей анимации. Профили, использующие одну модель, сохраняют отдельные экземпляры. Без принятой анимации раскрепления удаление происходит мгновенно.

Опциональный клиент Fabric требует протокол 9 для наложения отображения панели быстрого доступа. Обновите его JAR вместе с плагином.

## Передача владения

Отображаемая копия принадлежит сессии презентации. С помощью `render.dynamic-items.defer-until-equipped` исходящая модель сохраняет своё определение предмета и компоненты через действие «снятие/отложенное». Приходящее снаряжение получает текущие предметы инвентаря. Это меняет только презентацию, а не настоящий предмет, его длительность, урон, патроны или состояние оружия.

Проверьте выбор источника/статического правила с помощью **актуального финального пакета поставщика**, включая активные наложения. Определение, видимое в отдельном ZIP-архиве для тестирования, может не совпадать с тем, что доставляет поставщик.
