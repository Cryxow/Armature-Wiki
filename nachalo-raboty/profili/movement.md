# 🏃 Правила движения

Правила движения используют `when`. Armature оценивает совпадающие правила, выбирает наиболее специфическое условие и использует порядок объявления только в качестве последнего средства для разрешения ничьих. Для движения `priority` не требуется.

Правило движения `animation.sway-rate` перекрывает множитель раскачивания модели только в то время, когда это правило выбрано. Если оно отсутствует, движение использует `model.sway-rate`. Явное значение `0.0` отключает процедурное раскачивание для этого движения.

```yaml
animations:
  movement:
    - when:
        - player.climbing == true
        - player.climbing-direction == up
      animation: climb-up

    - when:
        - player.climbing == true
        - player.climbing-direction == down
      animation: climb-down

    - when:
        - player.falling == true
      animation:
        name: fall
        start: fall-start
        end: fall-end
```

`player.climbing-direction` — это `up`, `down` или `none`. Для свободного падения используйте `player.falling` или `player.vertical-speed < 0`. Для плавного отклика падения используйте аддитивный вес, управляемый `player.fall-distance`.

## Варианты анимации

С `render.backend: native` имена активов анимации выбираются свободно, включая `idle`, `walk`, `idle_fly`, `walk_fly`, `spawn` и `jump`. Правила движения/действия/аддитивности и их клипы начала/конца/ссылок используют явно настроенные имена. Клипы не начинаются автоматически из-за имени. Эта политика применяется к наследуемым профилям и представлениям API при запуске и перезагрузке профиля. Имена должны быть непустыми и соответствовать клипу в модели. Бэкенд BetterModel сохраняет свою валидацию имен с зарезервированными именами.

Каждое `animation` принимает либо одно имя актива, либо сопоставление:

```yaml
animation:
  name: [swing, swing_1, swing_2]
  selection: random
  duration: 6t
  speed: 1.0
  cooldown: 3t
  can-be-cancelled: true
```

| Поле | Движение | Действие | Аддитивное | Значение |
| --- | --- | --- | --- | --- |
| `name` | да | да | да | Один актив или список вариантов. |
| `arms` | необязательно | необязательно | нет | `one` (по умолчанию) или `both`. Движение/действие в основной руке может использовать оба скелета. |
| `selection` | да | да | да | `sequence` или `random`. По умолчанию `sequence`. |
| `speed` | да | да | да | Множитель воспроизведения, отличный от нуля. Отрицательные значения проигрывают анимацию в обратном порядке. |
| `blend-in` | необязательно | необязательно | нет | Длительность смешивания при входе. По умолчанию `2t` для движения и `1t` для действия. |
| `blend-out` | необязательно | необязательно | нет | Длительность смешивания при выходе. По умолчанию `2t`; `0t` отключает его. |
| `sway-rate` | да | нет | нет | Опциональное перенаправление движения. Наследует `model.sway-rate`, если не указано. |
| `loop` | true | false/не указано | n/a | Правила движения должны быть циклическими. |
| `start` | необязательно | нет | нет | Одноразовая анимация перед циклом движения. |
| `end` | необязательно | нет | нет | Одноразовая анимация после выхода из цикла движения. |
| `duration` | нет | необязательно | нет | Длительность действия резервного варианта, в тиках или секундах. |
| `cooldown` | нет | необязательно | нет | Задержка между успешными действиями. По умолчанию `3t`. |
| `can-be-cancelled` | нет | необязательно | нет | Может ли другое действие замены прервать его. По умолчанию `true`. |

Для конечных действий приоритет имеет известная длительность анимации рендера перед настроенной длительностью резервного варианта. `selection: sequence` продвигается после каждого успешного действия; `random` выбирается независимо для каждого действия. Охлаждение разделяется всеми вариантами одного правила.

## Базовое правило и конкретное правило

```yaml
animations:
  movement:
    - animation: base
    - when: player.sprinting == true
      animation:
        name: sprint
        speed: 1.0
        blend-in: 2t
        blend-out: 2t
```

Безусловное правило обеспечивает базовое значение. Условия более специфичного совпадения имеют приоритет. Порядок объявления нарушает равенство специфичности. Это отличается от выбора варианта, где выигрывает первый подходящий вариант. `0t` смешивание отключает эту сторону. Имена правил не выбирают клипы автоматически.
