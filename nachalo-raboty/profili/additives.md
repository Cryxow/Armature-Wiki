# ➕ Аддитивные слои

Аддитивные слои оцениваются непрерывно и накладываются на текущую рендеринговую позу движения/действия. Они не являются режимами действий:

```yaml
animations:
  additives:
    - animation:
        name: breathing
        speed: 1.0
      playback: loop
      bones: [body, right_arm, left_arm]
      weight:
        parameter: variable.stamina
        input: [0.0, 100.0]
        output: [1.0, 0.15]
        easing: smoothstep
```

Разделы движения и анимации действий также принимают `blend-in` и `blend-out` внутри своей `animation` карты. Длительности выражаются в тиках (`4t`) или секундах (`0.3s`). Числовые значения — это тики. По умолчанию сохраняется историческое поведение рендерера (`2t`/`2t` для циклов и `1t`/`2t` для действий), а `0t` отключает одну сторону смешивания.

Поддерживаемые поля аддитивных слоев: `when`, `animation`, `playback` (`loop`, `hold` или `once`), `group`, `priority`, `weight`, `blend-in`, `blend-out`, `bones`, `channels`, `position-gain`, `rotation-gain` и `reference`.

`reference.animation` и `reference.time` определяют позу, из которой берется аддитивный дельта. Концептуально:

```text
final pose = base pose + sum(additive delta * resolved weight)
```

Это поддерживаемое решение для высоты падения, дыхания, зависящего от выносливости, и аналогичного непрерывного контроля поз. Аддитивные слои комбинируют отобранные дельта над выбранной позой движения/действия.

## Выберите затронутые кости

Аддитивные слои комбинируют отобранную позу с текущим представлением движения/действия. Используйте `bones`, `channels`, `position-gain`, `rotation-gain` и `reference` для ограничения их вклада. Авторизованные цели костей должны существовать, и версия 2 не переписывает их для другой руки. Правила аддитивных слоев не принимают `arms: both`. Принадлежность руки принадлежит движениям/действиям.

## Сначала используйте небольшой вес

Начните с фиксированного `weight: 0.25`, а затем добавьте параметрические сопоставления после проверки корректности позы. Динамический ответ при падении может сопоставить `player.fall-distance` из `[0, 4]` в `[0, 1]` с помощью `smoothstep`, вместо резкого переключения позы. Аддитивное правило имеет свои собственные длительности смешивания. Имя анимации, выбор и скорость должны находиться внутри сопоставления `animation`.

Ссылки на клипы/время определяют нейтральную позу для аддитивной разницы. Отсутствие ссылочных костей/клипов является ошибкой активов, включая неактивные варианты. Протестируйте несколько одновременных групп, смешивания входа/выхода и разреженные треки против авторизованной позы покоя.
