# 🔀 Условия

Здесь описаны встроенные условия для современных профилей анимации предметов. Парсер и движок поддерживают базовые значения из таблиц ниже. Значения провайдеров, PlaceholderAPI, NBT и ресурсоёмкие вычисляемые значения могут быть недоступны, если отсутствует их источник. Встроенные значения, данные провайдеров и переменные администратора разделены по пространствам имён.

Условия используют `when` для правил движения/аддитивных и `condition` для правил действий. Канал действий всегда `replace`. В современном формате нет `action.mode`.

## Базовый синтаксис

Условия в списке `when` объединяются с `AND`:

```yaml
when:
  - player.on-ground == true
  - player.sneaking == false
  - player.speed < 2
```

В выражениях сравнения доступны следующие операторы.

```text
==       equals
!=       differs
<        less than
<=       less than or equal to
>        greater than
>=       greater than or equal to
in       belongs to a list or range
contains contains a value
```

Для групповой логики может поддерживаться явный вид:

```yaml
when:
  all:
    - player.on-ground == true
    - any:
        - player.sprinting == true
        - player.movement-direction == forward
  not:
    - player.sneaking == true
```

Один и тот же движок условий должен быть доступен для правил движения, событий действий и аддитивных анимаций. Правила движения выбирают одну базовую анимацию. Аддитивные правила могут быть активны одновременно.

## Пространства имен

| Пространство имен | Владение | Примеры |
| --- | --- | --- |
| `player.*` | Встроенное состояние игрока Armature | `player.speed`, `player.swimming` |
| `input.*` | Состояние ввода клиента Armature | `input.forward`, `input.jump` |
| `item.*` | Текущий предмет и экипировка | `item.main-hand.type` |
| `world.*` | Мир и контекст времени | `world.is-day`, `world.weather` |
| `block.*` | Блоки вокруг игрока | `block.below.type` |
| `movement.*` | Текущее состояние решателя движения | `movement.active`, `movement.changed` |
| `action.*` | Текущее состояние действий | `action.active`, `action.progress` |
| `animation.*` | Текущее состояние анимации | `animation.id`, `animation.remaining` |
| `additive.*` | Состояние аддитивного слоя | `additive.breathing.weight` |
| `event.*` | Текущее событие и его аргументы | `event.signal`, `event.argument.mode` |
| `variable.*` | Профильные/сессийные/внешние значения | `variable.stamina` |
| `<provider>.*` | Адаптеры внешних плагинов | `weaponmechanics.ammo` |
| `placeholder.*` | Явные значения PlaceholderAPI | `placeholder.player-stamina` |

`<provider>.*`, `variable.*` и `placeholder.*` не являются встроенными условиями игрока, но относятся к одному и тому же языку условий. Имя провайдера — это само пространство имен. Общий префикс `provider.` не доступен пользователям.

Имена событий используют одно и то же пространство имен источника с разделителем двоеточие: `weaponmechanics:reload`, `player:attack` или `block:break`. Значения используют точку для обращения к свойству в этом пространстве имен, например `weaponmechanics.ammo` или `player.speed`.

Правила визуализации предмета в руке открывают `item.using` (булево) и `item.use-ticks` (прошедшие тики использования) для отрендеренной руки. Эти два значения оцениваются отдельно для каждой руки. Используйте их в `model.held-item.rules[].when`.

## Состояние игрока

### Поза и возможности

| Условие | Тип | Значение |
| --- | --- | --- |
| `player.on-ground` | логическое значение | Игрок опирается на землю. |
| `player.moving` | логическое значение | Игрок имеет осмысленное горизонтальное перемещение. |
| `player.sneaking` | логическое значение | Игрок крадётся или присел. |
| `player.sprinting` | логическое значение | Игрок бежит. |
| `player.swimming` | логическое значение | Игрок находится в позе/состоянии плавания. |
| `player.falling` | логическое значение | Игрок падает вниз. |
| `player.jumping` | логическое значение | Игрок только что начал прыжок вверх. |
| `player.climbing` | логическое значение | Игрок находится на поверхности, по которой можно взбираться. |
| `player.gliding` | логическое значение | Игрок планирует на элитрах. |
| `player.flying` | логическое значение | Игрок летит, а не падает в обычном режиме. |
| `player.riding` | логическое значение | Игрок едет на транспортном средстве или сущности. |
| `player.passenger` | логическое значение | Игрок перевозится как пассажир. |
| `player.sleeping` | логическое значение | Игрок спит. |
| `player.using-item` | логическое значение | Игрок в данный момент использует предмет. |
| `player.blocking` | логическое значение | Игрок активно блокирует. |
| `player.swinging` | логическое значение | Игрок находится в анимации маха рукой. |
| `player.dead` | логическое значение | Игрок мертв или находится в состоянии смерти. |
| `player.spectator` | логическое значение | Игрок находится в режиме наблюдателя. |
| `player.invisible` | логическое значение | Игрок невидим. |
| `player.has-vehicle` | логическое значение | У игрока есть транспортное средство. |

`player.pose` может открыть скрытую позу в виде перечисления, когда одного булевого значения недостаточно, например `standing`, `crouching`, `swimming`, `fall-flying`, `sleeping`, `riding`, `spin-attack` или `dying`.

### Значения движения

| Условие | Тип | Значение |
| --- | --- | --- |
| `player.speed` | число | Нормализованная горизонтальная скорость движения. |
| `player.horizontal-speed` | число | Модуль горизонтальной скорости. |
| `player.vertical-speed` | число | Значенная вертикальная скорость. Положительное значение указывает вверх. |
| `player.total-speed` | число | Полный модуль вектора скорости движения. |
| `player.fall-distance` | число | Пройденное расстояние вниз с момента отрыва от земли. |
| `player.air-time` | длительность | Время с момента отрыва от земли, в тиках. |
| `player.time-since-grounded` | длительность | Время с момента последнего состояния стояния на земле, в тиках. |
| `player.jump-time` | длительность | Время с момента начала текущего прыжка, в тиках. |
| `player.distance-to-ground` | число | Оцененное расстояние до следующей твердой поверхности. Опционально и более затратно. |
| `player.acceleration` | число | Изменение горизонтальной скорости. Опциональное выведенное значение. |

`player.speed` должен иметь один документированный единицу и оставаться стабильным на всех реализациях сервера. `player.horizontal-speed` должен быть доступен, когда требуется точная скорость. `player.fall-distance` и `player.vertical-speed` должны быть независимыми значениями: одно описывает накопленное расстояние, другое — текущее направление и интенсивность.

### Направление

Краткая форма `player.direction` может поддерживаться, с `player.movement-direction` как явным именем.

```text
forward
backward
left
right
up
down
none
```

Направление отсчитывается относительно взгляда игрока, а не координат мира. `up` и `down` применимы при лазании и другом вертикальном движении. Движок определяет основное горизонтальное направление (`forward`, `backward`, `left` или `right`). Чтобы различать диагональный ввод, используйте логические значения ввода.

Два источника должны оставаться разделенными:

| Условие | Значение |
| --- | --- |
| `input.direction` | Направление, в котором игрок пытается двигаться. |
| `player.movement-direction` | Направление, в котором игрок фактически движется. |
| `player.climbing-direction` | `up`, `down` или `none` во время лазания. |
| `player.look-direction` | Направление взгляда игрока, а не движения. |

Выбор анимации обычно должен основываться на реальном движении. Направление ввода полезно, когда анимация должна реагировать мгновенно на нажатую клавишу, даже если игрок заблокирован.

### Состояние ввода

Условия ввода полезны для действий с триггером и для различения намерения от результирующего движения:

| Условие | Тип | Значение |
| --- | --- | --- |
| `input.forward` | логическое значение | Ввод вперед удерживается. |
| `input.backward` | логическое значение | Ввод назад удерживается. |
| `input.left` | логическое значение | Ввод влево удерживается. |
| `input.right` | логическое значение | Ввод вправо удерживается. |
| `input.jump` | логическое значение | Ввод прыжка удерживается или активен. |
| `input.sneak` | логическое значение | Удерживается клавиша крадущегося движения. |
| `input.sprint` | логическое значение | Ввод бегства удерживается. |
| `input.just-pressed.<name>` | логическое значение | Ввод был нажат в этом обновлении. |
| `input.just-released.<name>` | логическое значение | Ввод был отпущен в этом обновлении. |

### Блоки рядом

Условия блоков должны быть ограничены фиксированными позициями вокруг игрока и не должны выполнять бесконечные поиски:

| Условие | Тип | Значение |
| --- | --- | --- |
| `block.below.type` | материал | Блок непосредственно под игроком. |
| `block.above.type` | материал | Блок непосредственно над игроком. |
| `block.current.type` | материал | Блок в позиции игрока. |
| `block.below.solid` | логическое значение | Блок под игроком твердый. |
| `block.current.liquid` | логическое значение | Текущий блок — жидкость. |
| `block.below.slipperiness` | число | Скользкость поверхности под игроком. |
| `block.below.climbable` | логическое значение | Блок под или рядом с игроком взбираемый. |

Регионы, территории, разрешения и произвольные поиски nearby-entities должны предоставляться специализированными интеграциями, а не добавляться в базовый словарь.

| `player.on-fire` | логическое значение | Игрок горит. |
| `player.freezing` | логическое значение | Игрок замерз. |

```yaml

  - player.has-effect:speed == true

```

Для глобального отключения игрока используйте временные разрешения `armature.disabled` или `armature.disabled.<profile-id>` вместо повторения условия разрешения в каждом правиле. `player.has-permission` остается полезным для условий анимации, специфичных для правила.

## Анимация и состояние сессии

Эти значения позволяют событиям и правилам анимации реагировать на собственное состояние времени выполнения Armature без чтения внутренних деталей движка рендеринга.

### Состояние движения

| Условие | Тип | Значение |
| --- | --- | --- |
| `movement.active` | логическое значение | Правило движения сейчас совпадает. |
| `movement.id` | строка | Идентификатор выбранного правила движения. |
| `movement.previous` | строка | Ранее выбранное правило движения. |
| `movement.changed` | логическое значение | Выбранное движение изменилось в этом обновлении. |
| `movement.entered` | логическое значение с параметром | Было введено названное движение. |
| `movement.left` | логическое значение с параметром | Было оставлено названное движение. |
| `movement.transitioning` | логическое значение | Переход между движениями находится в процессе. |
| `movement.transition-progress` | число | Прогресс перехода от `0.0` к `1.0`. |

### Состояние действия

| Условие | Тип | Значение |
| --- | --- | --- |
| `action.active` | логическое значение | В настоящее время воспроизводится действие. |
| `action.id` | строка | Идентификатор текущего действия. |
| `action.progress` | число | Прогресс текущего действия от `0.0` до `1.0`. |
| `action.elapsed` | длительность | Время, прошедшее с начала действия. |
| `action.remaining` | длительность | Оставшееся время действия. |
| `action.completed` | логическое значение | Текущее действие завершилось в этом обновлении. |
| `action.cancelled` | логическое значение | Текущее действие было отменено в этом обновлении. |
| `action.interruptible` | логическое значение | Текущее действие может быть заменено. |
| `action.cooldown-ready` | логическое значение с параметром | Названное действие может сработать снова. |

Современные действия всегда используют эксклюзивный канал `replace`. Правила аддитивности предоставляют отдельный канал непрерывного композирования. Они не устанавливают режим действия.

### Состояние добычи

| Условие | Тип | Значение |
| --- | --- | --- |
| `block.mining` | логическое значение | Сессия добычи в основной руке активна. |
| `block.mining.elapsed` | длительность | Количество тиков, прошедших с начала добычи. |
| `block.mining.block` | строка | Блок с пространственным именем, который добывается. |
| `block.mining.tool` | строка | Предмет с пространственным именем в основной руке. |
| `block.mining.face` | перечисление | Лицо блока, которое добывается. |
| `block.mining.instant` | логическое значение | Последний отчёт о повреждении блока указывает мгновенное разрушение. |

`block.mining.elapsed` — это прошедшее время, а не процент: публичные события Bukkit не предоставляют процент разрушения блока на сервере. Используйте булево состояние для цикла и сигналы `block:mining-start`/`block:mining-stop` для запуска и завершения анимации в один проход. Режим творчества не имеет сессии прогресса добычи выживания, но повторяющиеся сигналы начала/разрушения блока поддерживают активным `block.mining`, пока игрок продолжает бить блоки. Он истекает через восемь тиков без нового удара. Идентификатор последнего блока, отличного от воздуха, сохраняется, когда вызов пакета видит блок, уже удалённый разрушением.

| `animation.progress` | число | Текущий прогресс анимации. |
| `animation.elapsed` | длительность | Время с момента начала анимации. |
| `animation.remaining` | длительность | Оставшееся время. |
| `animation.marker` | логическое значение с параметром | Достигнутая метка с именем в этом обновлении. |
| `animation.loop-index` | число | Текущая итерация цикла. |
| `additive.active` | логическое значение | Активен хотя бы один аддитивный слой. |
| `additive.<id>.active` | логическое значение | Активен именованный аддитивный слой. |
| `additive.<id>.weight` | число | Текущий вес именованного аддитивного слоя. |

## Контекст события и времени

Эти условия имеют смысл только при оценке события или вызова:

| Условие | Тип | Значение |
| --- | --- | --- |
| `event.type` | строка | Нормализованный тип события. |
| `event.signal` | Именованная строка. | Внешнее или сигнальное сообщение от провайдера. |
| `event.source` | перечисление | Встроенное, провайдер, Skript, Denizen, API или метка. |
| `event.argument.<name>` | Значение, переданное в событие. | Время с момента запуска события. |
| `event.elapsed` | длительность | Время с начала сессии профиля. |
| `session.age` | длительность | Это первая активация сессии. |
| `session.first-equip` | логическое значение | Готово к использованию предустановленное время ожидания. |
| `cooldown.<id>.ready` | логическое значение | Оставшееся время ожидания. |
| `cooldown.<id>.remaining` | длительность | Пользовательские и внешние значения |

## Пользовательские и внешние значения

Встроенные условия должны оставаться стабильными и дешевыми. Пользовательские значения могут расширять ту же синтаксическую структуру. Объявите общие переменные в `plugins/Armature/variables.yml`:

```yaml
variables:
  stamina:
    type: number
    source: placeholderapi
    placeholder: "%player_stamina%"
    refresh: 2t
```

Затем ссылайтесь на них в профиле:

```yaml
animations:
  additives:
    - animation: breathing
      weight:
        parameter: variable.stamina
        input: [0, 100]
        output: [1.0, 0.15]
```

Игровое состояние, специфичное для поставщика, должно оставаться в именном пространстве:

Armature должен экспонировать значения поставщика через адаптеры, но не должен изобретать общие встроенные условия для патронов, урона, перезарядки, маны или другого игрового состояния.

```yaml
when:
  - weaponmechanics.ammo == weaponmechanics.magazine-size
  - weaponmechanics.aiming == false
```

Armature должен экспонировать значения провайдеров через адаптеры, но не должен изобретать общие встроенные условия для патронов, урона, перезарядки, маны или других состояний игры.



## Условия, привязанные к выбору

`match.when` и выбор вариантов используют внешнее состояние/общие переменные, а не результаты анимации или выбранного варианта/аксессуара. Условия установки могут использовать выбранный `variant.active` профиля, но не активное состояние другой установки. Правила анимации могут использовать `variant.active` и `attachment.<id>.active`.

```yaml
when:
  permissions:
    any: [cosmetics.gold, cosmetics.admin]
    none: [cosmetics.disabled]
  all:
    - variable.weapon-skin == gold
```

Критерии в блоке условий структурированного типа объединяются с помощью И. Список прав `any` предоставляет альтернативы. [Переменные](variables.md) объясняет отсутствующие значения, типы и обновление. Доступность запроса зависит от контекста фактического времени выполнения/поставщика. Для использования источника требуется его установка и конфигурация.
