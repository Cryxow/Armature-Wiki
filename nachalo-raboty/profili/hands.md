# 👐 Основная и вторая рука

Armature хранит отдельный контекст рендеринга для каждой руки. Селекторы,
идентификаторы предметов от провайдеров и условия для предмета в руке
проверяются для соответствующей руки. Если провайдер передаёт сведения
о руке в событии, Armature учитывает их при его обработке.

## Анимация обеих рук

В анимациях движения и действия можно указать `arms: one` (по умолчанию)
или `arms: both`. Правило основной руки с `both` может управлять
обеими руками на время движения или действия. Для аддитивных слоёв
параметр недоступен.

```yaml
animations:
  actions:
    - trigger: weaponmechanics:reload
      animation:
        name: reload
        arms: both
        can-be-cancelled: false
```

Используйте этот параметр с моделью и клипом, созданными для обеих рук.
Для формата `.armature` v2 отдельно задайте кости, клипы и цели
аддитивных слоёв для левой руки. У старых моделей `.bbmodel` действуют
свои правила адаптации второй руки.

## Отображение предметов при переключении

Параметр `render.dynamic-items.defer-until-equipped: true` сохраняет
предметы предыдущей модели на время анимации убирания предмета или
защищённой анимации. Новая модель получает текущие предметы в момент
начала анимации взятия предмета. Выбор в инвентаре и игровой процесс
остаются мгновенными. Правило действует и на сервере, и при рендеринге
через Fabric.

## Проверка обеих рук

Проверьте предметы, атаку и использование отдельно для каждой руки.
Протестируйте защищённое действие обеими руками, быстрое переключение
ячеек и переход на обычный предмет с возвратом к исходному профилю.
С клиентским модом проверьте, что после принятия пакета данных клиент
перехватывает рендеринг, а предыдущие объекты удаляются.
В [руководстве по переходу на серверный рендеринг](../../klientskii-mod/rendering-fallback.md)
объясняется, почему некоторые составные модели отображаются сущностями
на сервере.
