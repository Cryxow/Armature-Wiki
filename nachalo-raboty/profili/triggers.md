# ⚡ Триггеры

Триггеры — это мгновенные сигналы в пространстве. Постоянное состояние должно находиться в `animations.movement` или `animations.additives`. Оно не должно вызывать действие на каждом тике.

Современное дерево хранит все правила в одном контейнере `animations`. Правила действий используют `trigger` и опциональный `condition`. Их канал воспроизведения всегда исключительный `replace`, поэтому `mode` не является валидным полем.

```yaml
animations:
  actions:
    - trigger: player:attack
      condition:
        - player.using-item == false
      animation:
        name: [swing, swing_1, swing_2]
        selection: random
        duration: 6t

    - trigger: weaponmechanics:reload
      condition:
        - weaponmechanics.aiming == false
      animation:
        name: inspect
        duration: 20t
      consume: true
```

Все аргументы событий экспонируются во время оценки как `event.argument.<name>`. Несколько правил могут использовать один триггер. Наиболее точное совпадающее условие выигрывает, затем порядок объявления служит резервным вариантом.

Статус: `implemented` испускается базовым плагином; `provider` требует именного опционального провайдера; `API/Skript/Denizen` означает, что внешний вызывающий может опубликовать его; `reserved` является частью словаря, но у него пока нет встроенного испускающего элемента.

## Политика именного пространства

| Именное пространство | Источник | Примеры | Статус |
| --- | --- | --- | --- |
| `player:` | нормализованное событие игрока | `player:attack` | поддерживается |
| `item:` | цикл жизни предмета/профиля | `item:equip` | поддерживается |
| `block:` | взаимодействие с блоком/добыча | `block:place` | поддерживается |
| `entity:` | взаимодействие с сущностью/бой | `entity:hit` | поддерживается |
| `projectile:` | запуск/влияние снаряда | `projectile:hit` | поддерживается |
| `world:` | переход мира/окружения | `world:change` | поддерживается |
| `input:` | Ввод клиента или намерение, переданное пакетом | `input:jump-press` | поддерживается |
| `animation:` | жизненный цикл анимации Armature/маркер | `animation:complete` | поддерживается |
| `<provider>:` | адаптер внешнего плагина | `weaponmechanics:reload` | поставщик |
| `<integration>:` | сигнал, принадлежащий внешнему вызывающему | `skript:weapon.special` | API/Skript/Denizen |

Префикс `armature:` отсутствует. Поставщик или интеграция владеет своим пространством имен. Armature разрешает сигнал только относительно активного профиля предмета.

## Действия игрока и взаимодействия

| Триггер | Когда срабатывает | Полезные аргументы | Статус |
| --- | --- | --- | --- |
| `player:attack` | Обнаружена атака или взмах основной рукой. | `hand`, `target`, `critical` | поддерживается |
| `player:use-item` | Нажатие клавиши / клик правой кнопкой мыши. | `hand`, `item`, `action` | поддерживается |
| `player:use-item-stop` | Использование предмета завершается до окончания анимации. | `hand`, `item`, `reason` | поддерживается |
| `player:use-item-complete` | Использование предмета завершено. | `hand`, `item` | поддерживается |
| `player:consume-item` | Еда, зелье или расходный предмет были использованы. | `hand`, `item` | поддерживается |
| `player:release-item` | Игрок отпускает удерживаемый или заряженный предмет. | `hand`, `item`, `charge` | поддерживается |
| `player:swap-hand` | Выполнен запрос на смену предмета в основной или второй руке. | `previous-main-hand`, `previous-off-hand` | поддерживается |
| `player:drop-item` | Игрок бросает предмет. | `hand`, `item`, `amount` | поддерживается |
| `player:pickup-item` | Игрок поднимает предмет. | `item`, `amount` | поддерживается |
| `player:hotbar-change` | Изменен выбранный слот в панели быстрого доступа. | `previous-slot`, `slot`, `item` | поддерживается |
| `player:interact` | Обычное взаимодействие игрока происходит. | `hand`, `action`, `target` | поддерживается |

`player:use-item` и `input:secondary-press` представляют намерение правого клика, включая клики в воздухе, где ванильная версия не имеет действия с предметом. Paper по умолчанию может отменять эти `PlayerInteractEvent`. Armature продолжает отслеживать ввод.

`player:attack` включает классификацию цели, вычисленную в момент замаха: `event.argument.target` — это `air`, `block` или `entity`. Более точный `event.argument.target-type` содержит тип блока/сущности с именем пространства или `minecraft:air`. Это цель луча на сервере до того, как другой плагин отменит или изменит получившийся урон.

```yaml
actions:
  - trigger: player:attack
    condition: event.argument.target in [air, entity]
    animation:
      name: [sword_swing_1, sword_swing_2]
      selection: sequence

  - trigger: block:damage
    animation:
      name: block_swing
```

## Переходы движения

Циклы движения должны использовать `when`, например `player.climbing == true` и `player.climbing-direction == down`. Эти сигналы предназначены для однократных анимаций переходов.

| Триггер | Когда срабатывает | Статус |
| --- | --- | --- |
| `player:move-start` | Значимое движение начинается. | поддерживается |
| `player:move-stop` | Значимое движение заканчивается. | поддерживается |
| `player:sprint-start` | Бег начинается. | поддерживается |
| `player:sprint-stop` | Бег заканчивается. | поддерживается |
| `player:sneak-start` | Игрок начинает красться. | поддерживается |
| `player:sneak-stop` | Игрок прекращает красться. | поддерживается |
| `player:jump` | Начало прыжка вверх. | поддерживается |
| `player:land` | Игрок вернулся на землю. | поддерживается |
| `player:fall-start` | Начало движения вниз в воздухе. | поддерживается |
| `player:fall-stop` | Конец движения вниз. | поддерживается |
| `player:climb-start` | Начание лазания. | поддерживается |
| `player:climb-stop` | Конец лазания. | поддерживается |
| `player:swim-start` | Начание плавания. | поддерживается |
| `player:swim-stop` | Плавание заканчивается. | поддерживается |
| `player:glide-start` | Игрок начинает планировать на элитрах. | поддерживается |
| `player:glide-stop` | Игрок перестаёт планировать на элитрах. | поддерживается |
| `player:mount` | Игрок садится в транспорт или на сущность. | поддерживается |
| `player:dismount` | Игрок покинул транспортное средство/сущность. | поддерживается |
| `player:direction-change` | Изменилось направление относительного движения. | поддерживается |

Детали перехода включают `speed`, `vertical-speed`, `fall-distance`, `fall-time`, `direction` и `previous-direction`.

| Триггер | Когда срабатывает | Статус |
| --- | --- | --- |

| `item:held-change` | Изменился распознанный идентификатор предмета в руке. | поддерживается |
| `item:main-hand-change` | Изменена слот предмета в основной руке. | поддерживается |
| `item:off-hand-change` | Изменился предмет во второй руке. | поддерживается |

## Блоки, сущности и снаряды

| Триггер | Когда срабатывает | Полезные аргументы | Статус |
| --- | --- | --- | --- |
| `block:break-start` | Клиент начинает копать. | `phase: start` | поддерживается |
| `block:damage` | Bukkit сообщает о повреждении блока, обычно в начале. | `block`, `tool`, `face`, `phase` | поддерживается |
| `block:break` | Разрушение блока завершено. | `block`, `tool`, `phase: complete` | поддерживается |
| `block:mining-start` | Сессия копания началась. | `block`, `tool`, `face`, `elapsed: 0` | поддерживается |
| `block:mining-stop` | Сессия копания завершена или отменена. | `block`, `tool`, `face`, `elapsed` | поддерживается |
| `block:place` | Установка блока успешна. | `block`, `against`, `face`, `hand`, `tool` | поддерживается |
| `block:interact` | Игрок взаимодействует с блоком. | `block`, `face`, `hand`, `action` | поддерживается |
| `entity:interact` | Игрок взаимодействует с сущностью. | `entity`, `hand`, `action` | поддерживается |
| `entity:hit` | Игрок наносит урон сущности. | `target`, `damage`, `damage-type` | поддерживается |
| `entity:death` | Сущность, которую убил игрок, умирает. | `entity`, `killer` | поддерживается |
| `projectile:launch` | Игрок запускает снаряд. | `projectile`, `item` | поддерживается |
| `projectile:hit` | Снаряд игрока попадает в сущность/блок. | `projectile`, `target`, `block` | поддерживается |

`block:break-start` поступает из PacketEvents и является сигналом намерения; `block:break` — это событие завершения. Это различие предотвращает воспроизведение анимации завершения при отмене добычи. Постоянное состояние экспонируется как `block.mining` и обновляется с игровым тиком. Armature не отправляет новый сигнал действия каждый тик. В режиме творения повторяющиеся сигналы «начать/разрушить» обновляют состояние добычи. Оно прекращается после восьми тиков без нового попадания, так как клиент не поддерживает сессию прогресса разрушения выживания.

## Провайдер и пользовательские триггеры

WeaponMechanics использует свой собственный namespace. Базовый адаптер нормализует события действий и передаёт детали провайдера, такие как `weaponmechanics.ammo`, `weaponmechanics.aiming`, `weaponmechanics.reloading`, `weaponmechanics.rounds-remaining` и `weaponmechanics.firearm-state`.

| Семейство сигналов | Примеры | Статус |
| --- | --- | --- |
| WeaponMechanics | `weaponmechanics:fire`, `weaponmechanics:reload`, `weaponmechanics:reload-phase`, `weaponmechanics:firearm-state-change`, `weaponmechanics:fire-mode-change`, `weaponmechanics:reload-complete` | провайдер |
| Java API | `api:custom-hit`, `custom:parry` | API |
| Skript addon | `skript:weapon.special` | API/Skript |
| Denizen | `denizen:weapon.parry` | API/Denizen |
| Другой плагин | `<plugin-id>:<event>` | API |

```yaml
animations:
  actions:
    - trigger: api:custom-hit
      condition:
        - event.argument.critical == true
      animation:
        name: hit
        duration: 6t
```

Java-вызовы используют `ArmatureApi.animations().sendSignal(playerId, signal, details)`. Skript и Denizen добавляют эквивалентные операции сигналов. Denizen также предоставляет нативные события жизненного цикла и сырые команды воспроизведения.

Плагины геймплея остаются ответственными за решение, успешно ли произошло событие геймплея. `consume: true` имеет смысл только тогда, когда владелец события разрешает отмену. Для внешних API-сигналов он возвращается как метаданные результата.


## Надевание и снятие

`item:equip` относится к входящему представлению. Принятое `item:unequip` сохраняет текущий экземпляр/позу для этого клипа, включая быстрые переключения и возврат к тому же профилю. Без принятого клипа снятия он удаляется немедленно. `render.dynamic-items.defer-until-equipped` сохраняет визуальный снимок предмета до момента, когда входящее представление наденется. Это никогда не задерживает выбор инвентаря или геймплей оружия.
