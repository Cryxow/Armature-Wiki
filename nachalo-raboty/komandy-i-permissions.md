# ⌨️ Команды и права доступа

Armature регистрирует Paper `BasicCommand` через регистратор команд жизненного цикла. Корневая команда — `/armature`. Paper также предоставляет `/arm` и `/armatureadmin`. `plugin.yml` хранит только метаданные команд Bukkit и строку использования, поэтому не объявляет конкурирующие алиасы.

Заголовки администратора используют `plugins/Armature/messages.yml`. Поддерживаются `locale: auto`, `en` и `fr`. Коды диагностики остаются независимыми от языка. Каждая команда требует `armature.command` в корне, а затем доменную привилегию. Поддерживаются отправители консоли, если команда явно не требует контекста игрока.

## Основные команды

```text
/armature help [domain]
/armature status
/armature reload [all|config|profiles|models|pack|providers]
/armature enable
/armature disable
/armature config ...
/armature profile ...
/armature animation ...
/armature editor
/armature diagnostics ...
/armature debug ...
```

Корневые сокращения `help`, `status`, `reload`, `enable`, `disable` и голые `editor` остаются доступными. `/armature help` перечисляет только домены, разрешенные отправителю. Домен `debug` опускается, если у отправителя нет `armature.command.native-probe`.

`help` принимает домен для показа контекстного использования, например `/armature profile help`. Предложения фильтруются по привилегиям и уже введенному тексту. Предоставляются дополнения для игрока, профиля, модели, анимации, файла миграции и нативного проба там, где это применимо.

## `/armature status`

Показывает активный бэкенд, время выполнения и переключатели рендеринга, настроенные количества моделей/профилей, недоступные настроенные анимации, количество поставщиков и метрики рендерера. Детали каталога нативного бэкенда включены, если нативный бэкенд загрузил каталог.

Привилегия: `armature.command.status`.

## Команды перезагрузки

Все перезагрузки используют `/armature reload <target>`:

| Цель | Операция |
| --- | --- |
| `config` | Перезагрузить и валидировать `config.yml` только. |
| `profiles` | Перезагрузить только файлы профиля. |
| `models` | Перезагрузить только активы модели рендерера. |
| `pack` | Пересобрать пакет ресурсов Armature. |
| `providers` | Запросить генерацию внешнего поставщика пакетов ресурсов без пересборки Armature. |
| `all` | Перезагрузить конфигурацию, профили, модели и пакет Armature. |

Без цели `/armature reload` перезагружает конфигурацию, профили и модели. Генерация пакетов следует по пути `resource-pack.generation.on-reload`. Явные цели `pack` и `all` генерируют пакет Armature даже при отключенных автоматических триггерах.

`all` перестраивает ресурсы Armature. Мосты поставщиков могут регенерировать свои пакеты при изменении этих активов. `/armature reload providers` явно запрашивает генерацию от поддерживаемых мостов CraftEngine и Nexo без перестройки Armature. ItemsAdder сохраняет свой собственный полный рабочий процесс генерации пакетов. Каждая операция сообщает о прошедших этапах и сохраняет последнюю известную рабочую версию, когда кандидат не проходит проверку. `/armature help reload` объясняет цели. Автодополнение перечисляет их.

Операции перезагрузки больше недоступны под `config`, `profile` или `diagnostics`. `/armature diagnostics startup` сообщает о состоянии и времени операции; `/armature diagnostics pack` сообщает о состоянии пакета без его изменения.

Разрешение: `armature.command.reload`.

## `/armature config`

```text
/armature config validate
/armature config migrate <file> [--output <file>] [--local|--ai]
/armature config restore-defaults [--confirm]
```

`validate` сообщает о результатах конфигурации без применения изменений.

`migrate` читает устаревший профиль относительно `plugins/Armature/profiles/` и записывает отдельный валидированный кандидат, по умолчанию `<name>.migrated.yml`. Он никогда не заменяет исходник или не перезагружает активную презентацию. `--local` и `--ai` являются флагами совместимости: оба используют локальный детерминированный конвертер, без сетевых вызовов. Исходные и кандидатские файлы имеют фиксированный внутренний лимит 256 КБ. В `config.yml` нет вариантов миграции. См. [Обновление до 2.0.0](upgrading.md) перед активацией вывода.

`restore-defaults` сначала выводит превью. Он перезаписывает совпадающие файлы из встроенного `default-assets/` только после того, как тот же отправитель повторит команду с `--confirm`. Затем выполните явную команду перезагрузки, соответствующую измененным файлам.

Разрешение: `armature.command.reload` для `validate` и `restore-defaults`; `armature.command.migrate-config` для `migrate`.

## `/armature profile`

```text
/armature profile list [player]
/armature profile inspect <player>
/armature profile enable <player> <profile>
/armature profile disable <player> <profile>
```

Без игрока `list` отображает настроенные ID профилей. С онлайн-игроком отображаются отключения профилей, управляемые командой. `inspect` является только для чтения и сообщает о текущем разрешении, наблюдаемом сервером. Он не утверждает, что подключенный клиент отрендерил результат.

`enable` и `disable` управляют постоянным отключением профиля на основе UUID. Отключения на основе разрешений сохраняют приоритет выше состояния, управляемого командой.

Разрешение: `armature.command.profile`.

## `/armature animation`

```text
/armature animation play <player> <model> <animation>
/armature animation stop <player>
```

`play` принимает любую модель, загруженную выбранным рендерером (`.bbmodel` или нативным `.armature`, используя её ID модели), и точное имя клипа. Целевой игрок должен быть онлайн. Не требуется совпадающая активная модель или профиль для запрашиваемой модели. Во время воспроизведения запрашиваемая модель временно заменяет представление предмета в руке, сохраняя смещение модели профиля, скорость покачивания и видимость руки по умолчанию. Без профиля предмета в руке применяются настройки по умолчанию. Временный просмотр использует только запрашиваемый клип, поэтому клипы, условия и аддитивные слои из предыдущей модели не могут блокировать воспроизведение. Отсутствующие модели или клипы отклоняются до замены текущего просмотра. После завершения анимации Armature восстанавливает профиль для предмета, который сейчас держит игрок, включая случаи, когда игрок изменил предмет во время воспроизведения. `stop` отменяет активное действие и прямой цикл цели, затем позволяет возобновиться нормальному состоянию представления.

Разрешение: `armature.command.play`.

## `/armature editor`

```text
/armature editor open
/armature editor close [--confirm]
/armature editor reset [item|profile] [--confirm]
/armature editor export [item|profile]
/armature editor undo
/armature editor redo
/armature editor set <bone> <pos|rot> <x> <y> <z>
/armature editor diff [item|profile]
/armature editor mirror <left|right>
```

Безымянный `/armature editor` — это сокращение для `editor open`. Редактору требуется, чтобы игрок держал предмет с активным профилем Armature и редактируемыми костями модели. Его диалог содержит ползунки и видимое состояние `temporary preview`. `editor set` позволяет вводить точные числовые значения позиции (пиксели) или вращения (градусы), если клиент не поддерживает ввод текста в диалоге.

`undo` и `redo` сохраняют ограниченную историю сессии (50 изменений). `diff` выводит базовую авторскую модель, несохраненный `temporary preview` и сохраненный `item-override` или `profile-override`. `mirror left` копирует соответствующие значения справа в левые кости; `mirror right` делает обратное и зеркалит знаки позиции и вращения по оси X.

`reset` выводит разрушающий превью `item-override`/`profile-override` и требует `--confirm`. Он удаляет сохраненные значения для этого диапазона и обновляет живое представление. `close` блокирует процесс, пока `temporary preview` не станет чистым. Повторите его с `--confirm`, чтобы отбросить эти несохраненные значения. `export` генерирует фрагмент YAML, готовый к профилю, для `editor-overrides.yml`, включает сводку несохраненных данных и никогда не изменяет исходную конфигурацию профиля.

Все три слоя значений явно указаны в сообщениях редактора: `temporary preview` является живым и несохраненным, `item-override` сохраняется для одного предмета/диапазона профиля, а `profile-override` сохраняется для каждого предмета, разрешенного этим профилем. Сохранение переопределения или применение превью изменяют только представление. Исходные файлы профиля никогда не изменяются редактором.

Разрешение: `armature.command.editor`.

## `/armature diagnostics`

```text
/armature diagnostics doctor
/armature diagnostics performance
/armature diagnostics pack
/armature diagnostics startup
/armature diagnostics export
```

`doctor` генерирует предварительный отчет с кодами стабильных находок, если они доступны. `performance` сохраняет существующую боковую панель босса, доступную только игрокам в режиме реального времени. `pack` сообщает о состоянии сгенерированного пакета и владения без пересборки или синхронизации активов. Используйте `/armature reload pack`, `/armature reload models` или `/armature reload providers` для этих операций. `startup` сообщает о состоянии работы в реальном времени и таймингах этапов. `export` немедленно планирует создание обезличенного, ограниченного пакета поддержки вне основного потока, а затем сообщает относительный путь `plugins/Armature/diagnostics/armature-support-<timestamp>.zip` после завершения атомарной операции перемещения архива. Значения конфигурации, содержащие учетные данные или конечные точки, идентификаторы игроков, IP-адреса и нерелевантные строки логов, обрезаются. Экспорт никогда не выполняет синхронные операции ввода-вывода архива в обработчике команды.

Разрешение: `armature.command.status` для `doctor`, `pack` и `export`; `armature.command.performance` для `performance`.

## `/armature debug`

```text
/armature debug native-probe <model> [animation]
/armature debug stress <entity-count> <model-name> <animation>
/armature debug stress clear
```

Запускает существующую нативную статическую модельную пробоотборную систему. Реализация также сохраняет свое поведение подготовки каталога, когда модель не передается, чтобы существующие рабочие процессы операторов не деградировали. Имена нативной модели и анимации завершаются из загруженного каталога.

`stress` создает квадратную сетку из до 1,024 временных нативных моделей перед вызывающим игроком. Каждая модель повторяет выбранную анимацию и видна только этому игроку. Сетка истекает через десять минут, очищается при отключении владельца или может быть удалена немедленно с помощью `stress clear`. Эта отладочная операция требует нативного движка рендеринга.

Разрешение: `armature.command.native-probe`.

## Формы команд совместимости

Устаревшие формы продолжают выполнять свою существующую операцию, а затем издают одно предупреждение с каноническим заменителем. Аргументы сохраняются в предупреждении.

| Устаревшая форма | Каноническая форма |
| --- | --- |
| `/armature perf` | `/armature diagnostics performance` |
| `/armature regenerate-defaults` | `/armature config restore-defaults` |
| `/armature migrate-config <file> [--output <file>]` | `/armature config migrate <file> [--output <file>]` |
| `/armature play <player> <model> <animation>` | `/armature animation play <player> <model> <animation>` |
| `/armature native-probe <model> [animation]` | `/armature debug native-probe <model> [animation]` |

`performance` продолжает приниматься как дополнительная написание устаревшей формы `perf` для совместимости с привычками старых операторов.

## Права отключения для отдельных игроков

Глобальные команды `enable` и `disable` влияют на рендеринг во время работы. Чтобы исключить игрока без изменения глобального состояния рендеринга, предоставьте одно из этих прав через плагин прав:

- `armature.disabled` отключает представление Armature для каждого профиля;
- `armature.disabled.<profile-id>` отключает только совпадающий профиль.

Например:

```text
/lp user Alice permission set armature.disabled.m4a1 true
```

Исключения на основе прав имеют приоритет над `/armature profile enable` и применяются на следующем тике игрока. Они не изменяют предмет в руке или состояние игры.

## Список прав доступа

| Право | Диапазон | По умолчанию |
| --- | --- | --- |
| `armature.command` | Доступ к корневой команде | op |
| `armature.command.status` | Статус, доктор, пакет, экспорт диагностики | op |
| `armature.command.performance` | Производительность босса | op |
| `armature.command.reload` | Явные операции конфигурации/профиля/модели/пакета/поставщика, валидация конфигурации, восстановление по умолчанию | op |
| `armature.command.toggle` | Включение/выключение в реальном времени | op |
| `armature.command.play` | Воспроизведение/остановка анимации | op |
| `armature.command.editor` | Операции редактора | op |
| `armature.command.profile` | Операции профиля | op |
| `armature.command.migrate-config` | Миграция legacy-профилей | op |
| `armature.command.native-probe` | Отладочные команды Armature | op |
| `armature.disabled` | Отказ игрока от участия | false |


Управление генерацией пакетов: `/armature reload pack` и `/armature reload all` явно генерируются даже при отключенных автоматических триггерах. Перезагрузка конфигураций/профилей/моделей подчиняется `resource-pack.generation.on-reload`. `/armature diagnostics pack` сообщает опубликованные параметры генерации, результаты валидации, размер и длительность. `/armature reload providers` запрашивает синхронизацию существующего поставщика. Он не обходит настройки генерации Armature.
